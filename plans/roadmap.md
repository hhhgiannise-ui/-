# TripAA 开发路线图（v1.0）

> 产品名：AA 旅行账本 · 代号：tripshare
> 定位：小圈子（家人/朋友）共享的旅行费用分摊小程序

## 阶段总览

```
Phase 0 需求与设计（文档先行）
  ├─ 0.1 PRD（docs/prd/PRD_v1.0.md）
  ├─ 0.2 项目指南（docs/design/project-guide.md）
  ├─ 0.3 数据库设计（docs/design/database-design.md）
  └─ 0.4 API 接口文档（docs/api/api-doc.md）

Phase 1 工程与基础设施
  ├─ 1.1 微信开发者工具创建小程序项目 + 接入 CloudBase
  ├─ 1.2 云函数骨架 + 本地开发环境跑通
  └─ 1.3 Git 远程仓库推送（GitHub/Gitee）

Phase 2 认证：微信一键登录
  ├─ 2.1 CloudBase 开通匿名/微信登录 + 小程序 AppID 绑定
  ├─ 2.2 登录云函数（openid → 用户档案 upsert）
  └─ 2.3 前端登录态管理（本地缓存 + 启动拉取）

Phase 3 核心数据：旅行 / 成员 / 账单
  ├─ 3.1 旅行 CRUD（创建、列表、详情、编辑）
  ├─ 3.2 成员管理（邀请码加入、退出、管理员）
  ├─ 3.3 账单 CRUD（金额、分类、付款人、分摊方式）
  └─ 3.4 图片上传（账单凭证、旅行照片墙）

Phase 4 后端逻辑：分摊与结算（云函数）
  ├─ 4.1 分摊算法（按人头平摊 / 按项目 / 代付抵扣）
  ├─ 4.2 结算状态机（未结算 → 已结算，欠款清单生成）
  ├─ 4.3 安全规则与越权校验（非成员不可读写）
  └─ 4.4 单元测试（分摊算法纯函数）

Phase 5 真机预览与打磨
  ├─ 5.1 全流程自测（建团→记账→算账→清账）
  ├─ 5.2 真机预览体验（个人小程序账号）
  └─ 5.3 细节打磨（空态、加载态、错误提示）

Phase 6（可选）提审上架
  └─ 6.1 类目选择、隐私协议、内容审核合规
```

## 关键决策（预记）

| 决策点 | 倾向方案 | 理由 |
|---|---|---|
| 前端 | 微信小程序原生（WXML/WXSS/JS）+ 微信云开发 SDK | 官方第一公民，文档最全 |
| 数据库 | CloudBase 文档型数据库（集合式） | 免运维、与小程序 SDK 天然集成 |
| 后端逻辑 | CloudBase 云函数（Node.js） | 替代自建服务器，专注业务 |
| 认证 | 微信开放能力（openid） | 小程序内一键登录，无需账号密码 |
| 分摊模型 | 三模式：平摊 / 按项目 / 代付抵扣 | 覆盖常见旅行场景，算法有挑战 |
