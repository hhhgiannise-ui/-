## 1. 项目概述

### 1.1 背景与问题

考研备考中，错题整理是最高频、最痛苦的动作：

- 拍照 → 抄题 → 查解析 → 复盘，环节割裂，**坚持不下去**；
- 传统错题本是**静态的**，只记录"正确答案"，从不追问"为什么错"；
- 对着解析看完就忘，**没有形成自己的思考链路**。

### 1.2 产品定位

**不告诉你答案的考研错题教练**：拍照录入 → AI 结构化分析 →（V2）苏格拉底式逐层追问逼你自己想通 →（V3）生成同类变式题 →（V4）按遗忘曲线在临界点推回复习。

### 1.3 目标用户

- **首要**：开发者本人（考研自用）；
- 扩展：考研学生群体（作品集方向）。

### 1.4 核心价值

> 把"抄错题"变成"想通错题"。AI 永远不直接给答案，直到你自己想通。

### 1.5 名词解释

| 名词 | 含义 |
|---|---|
| 错题 Mistake | 一道错题的主记录（原题图 + 题干 + 科目/来源） |
| 分析 Analysis | AI 结构化产出（错因/知识点/难度/步骤），**附属数据，不改原题** |
| 追问会话 ProbeSession | 一道错题上的一轮多轮追问（S0–S5 状态机） |
| 变式题 Variant | 由 AI 生成的同类题，需三重质量校验 |
| 复习调度 ReviewSchedule | 简化 SM-2 遗忘曲线调度（V4） |

## 2. 用户故事

- 作为**考研学生**，我想拍照快速录入错题，以便不错过任何一道。
- 作为**考研学生**，我想看到 AI 的结构化分析（错因/知识点/难度），以便定位薄弱点。
- 作为**考研学生**，我想按科目/知识点筛选错题，以便针对性复习。
- 作为**考研学生**（V2），我想被 AI 逐层追问而不是直接看答案，以便真正想通。
- 作为**考研学生**（V4），我想在遗忘临界点收到复习提醒，以便记得牢。

## 4. 业务规则

### 4.1 数据隔离

- 全部业务数据按 **openid** 隔离，仅本人可见；
- 云函数强制校验身份，数据库安全规则兜底。

### 4.2 原题不可变原则（核心）

- `mistake` 主集合只存原题图与用户校对的文本；
- **一切 AI 产出写入附属集合**（analysis / variant / probe_turn），支持重跑、对比版本、回滚；
- 触发重新分析时只新增分析版本，不修改原题。

### 4.3 AI 输出约束（V2 追问引擎系统提示词要点）

1. 禁止直接给出答案、最终结果或完整解题步骤；
2. 每次只输出一个追问，且指向学生上一轮回答中的**具体环节**；
3. 连续两次「不会」或已追问满 6 轮 → 允许三层递进提示（方向 → 关键公式 → 步骤框架）；
4. 学生明确要答案 → 给出完整解析，但记录 `end_reason=user_ask`（放弃率指标）。

### 4.4 护栏规则（代码硬编码，不交给模型判断）

- 轮次上限 6 轮；
- 大模型超时/异常 → 返回固定兜底话术，不中断会话；
- AI 调用计 token 落库（`ai_call_log`），每日限额防滥用。

### 4.5 合规

- 对外定位写「错题管理与学习工具」，**不写**辅导/培训/提分（避开学科培训类目红线）；
- 服务类目：工具 > 效率（或 教育 > 教育信息服务）；
- 个人主体免费自用，**不涉及微信支付**；
- 必须接微信内容安全接口（审核必查项）。

## 6. 验收标准

### 6.1 核心流程用例

| 用例 | 操作步骤 | 预期结果 |
|---|---|---|
| 首次登录 | 打开小程序 | 自动登录，用户集合建档 |
| 录入闭环 | 拍照上传 → 补录科目 → 保存 | 列表出现该题；状态 待分析→分析中→已分析 |
| 结构化分析 | 查看详情 | 展示错因/知识点/难度/步骤；原题未被修改 |
| 筛选 | 按科目筛选 | 仅显示该科目错题 |
| 越权访问 | 伪造他人 openid 请求数据 | 云函数拒绝 |
| OCR 校对 | 上传题目图片 → 自动识别 → 修改识别文本 → 保存 | 题干使用校对后文本，原图不变 |
| 内容安全 | 输入违规文本 | 请求被拦截 |

### 6.2 上线条件（真机预览）

- 上述用例全部通过；
- 真机可完整走通「登录 → 录题 → 分析 → 筛选 → 详情」闭环；
- Git 仓库已推送远程，README / 接口文档齐全。
